# 커뮤니티 문제 보고 조사

서브에이전트(general-purpose) 하나에 아래 틀로 맡긴다. 결과가 오기 전에는 내용을 추측해 쓰지 않는다.
steamcommunity.com 은 연달아 읽으면 429 를 주므로 `fetch_mods.py` 와 동시에 돌리지 않고, 1시간 넘게 걸리면
그때까지 본 것으로 마무리하게 한다.

## 프롬프트 틀

```
Project Zomboid Build <빌드>(<출시일>) 멀티플레이(호스트가 게임 메뉴 '서버 만들기'로 열고 친구가 Steam 초대로 들어오는 방식,
2~4명, 참가자 Steam 닉네임에 한글이 있을 수 있음, 놀 때마다 호스트가 새로 엶)에서 아래 모드를 쓸 예정이다.
이 조건(호스트 방식, 비ASCII 이름, 재시작 뒤 데이터)과 겹치는 보고는 따로 표시해라.
오늘은 <날짜>다. WebFetch 로 각 모드의
- 창작마당 페이지 https://steamcommunity.com/sharedfiles/filedetails/?id=<ID>
- 변경 기록 https://steamcommunity.com/sharedfiles/filedetails/changelog/<ID>
- 댓글 https://steamcommunity.com/sharedfiles/filedetails/comments/<ID>
- 토론(버그 게시판), 설명에 링크된 GitHub 저장소의 이슈
를 읽고 최근(약 4~6주) <빌드> 또는 멀티에서 생긴 오류·충돌 보고, 아래 팩 모드와의 충돌 보고, 작성자 공지(알려진 문제, 비호환 목록)를 모아라.
브라우저 자동화는 쓰지 말고 WebFetch 만 쓴다. 429 가 나면 잠시 쉬었다 읽는다. 1시간 안에 끝내고, 못 본 페이지는 '읽지 못함'으로 적는다.

후보: <번호 / Mod ID / 이름>
팩에 있는 모드(충돌 확인용): <data/mods.json 의 이름 목록>

보고(한국어): 모드별로 (a) 마지막 업데이트 날짜, (b) 문제 보고 요약·날짜·출처 URL, (c) 팩 모드와의 충돌 보고,
(d) 보고가 없으면 '확인된 보고 없음'과 본 댓글 수·기간. 추측은 추측이라고 표시. 마지막에 위험 높은 순 3~5줄 요약.
```

## 볼 것

- 작성자 답글이 있는지, 보고 뒤 업데이트로 고쳐졌는지(변경 기록 날짜와 보고 날짜를 맞춰 본다).
- "작동 안 함" 댓글이 어느 빌드 이야기인지. 빌드가 적혀 있지 않으면 날짜로 추정하고 추정이라고 적는다.
- 멀티 전용 문제(동기화, 다른 플레이어에게 안 보임, 호스트에서만 남, 데디에서만 남).
- 구독 수가 적고(수천 이하) 최근 공개된 모드는 보고가 없어도 "검증 적음"으로 본다.
